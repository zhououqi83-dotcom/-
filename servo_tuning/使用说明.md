# 舵机调试平台 使用说明

本平台用于调试 Droid 机器人的面部舵机。通过网页拖动滑块，可以实时控制机器人头部每一个舵机的位置；也可以通过 Blendshape 表情系数驱动多个舵机联动；还支持数字人与实体机器人同步联动。

---

## 整体架构（先看懂再操作）

```
[机器人硬件]
    ↕ 串口 (USB)
[底层 gRPC 服务]        ← 终端 1：打通软件与硬件的物理通信
    ↕ 网络 (gRPC, 端口 2543)
[servo_server.py]       ← 终端 2：WebSocket 转发层 + 硬件调试页面
    ↕ WebSocket (端口 8766)
[servo_tuning.html]     ← 浏览器：舵机调试操作界面
    ↕ (可选)
[数字人前端]            ← 终端 3 (可选)：高保真数字人可视化
```

**简单理解：** 需要按顺序启动三层服务，每层都正常，整个链路才通。

---

## 第一步：环境准备（只需做一次）

### 1.1 创建 Conda 虚拟环境

推荐使用 Python 3.10，避免依赖冲突：

```bash
conda create --name face_servo python=3.10 -y
conda activate face_servo
```

> 之后每次打开新终端都需要先执行 `conda activate face_servo`，否则找不到已安装的包。

### 1.2 安装 Python 依赖

```bash
# 安装基础依赖
pip install pyserial websockets

# 进入 head-sdk 目录安装 SDK
cd /servo_tuning/head-sdk-face/head-sdk
pip install rena2_sdk_api-0.1.0-py3-none-any.whl   # 安装 gRPC 通信协议包
pip install .                                     # 安装 head_sdk
```

**验证安装：**

```bash
python3 -c "from head_sdk import bs2servo; print('SDK 安装成功')"
```

输出 `SDK 安装成功` 则正常，否则检查上述步骤是否有报错。

### 1.3 安装前端依赖（可选，仅使用数字人功能时需要）

确保系统已安装 Node.js 和 npm，如未安装执行：

```bash
sudo apt install nodejs npm
```

然后安装前端依赖：

```bash
cd /servo_tuning/head-sdk-face/head-server-web/viewer/digital
npm install
```

## 第二步：硬件配置（换机器人或首次使用时做）

### 2.1 确认串口号

将机器人通过 USB 连接电脑，然后在终端运行：

```bash
ls /dev/ttyACM*
```

记下输出的设备名，例如 `/dev/ttyACM0`。

### 2.2 修改 YAML 配置文件

打开配置文件：

```
servo_tuning/head-sdk-face/head-server/src/servo_config_v3.yaml
```

找到 `controllers` 下的 `port` 字段，改为你上一步查到的串口号：

```yaml
controllers:
  - port: /dev/ttyACM0    # ← 改成实际串口号
```

---

## 第三步：启动服务

需要打开**两个终端**（如需数字人则三个），**按顺序**启动。

---

### 终端 1：启动底层 gRPC 服务

**作用：** 启动底层硬件驱动，打通电脑与机器人头部的物理通信。

```bash
conda activate face_servo
cd /servo_tuning/head-sdk-face/head-server/src
python head_grpc_server.py --config servoConfig_25DV3_Ula.yaml
```

启动成功后终端会持续打印日志，**不要关闭此窗口**。

> 如需连接特定型号机器人，`--config` 后换成对应配置文件，如 `servoConfig_25DV3_G01.yaml`。

---

### 终端 2：启动调试页面服务

**作用：** 启动 WebSocket 通信服务和硬件调试控制面板。

```bash
conda activate face_servo
cd /servo_tuning
bash run_servo_tuning.sh
```

启动成功后显示：

```
==========================================
  Servo Tuning Server
==========================================
HTTP Server: http://localhost:8081/servo_tuning.html
WebSocket:   ws://localhost:8766
==========================================
```

用浏览器打开：**http://localhost:8081/servo_tuning.html**

按 `Ctrl+C` 停止服务。

---

### 终端 3（可选）：启动数字人前端

**作用：** 启动高保真数字人 Web 界面，直观观察 BS 系数变化带来的表情表现，并与硬件端实现联动。

```bash
conda activate face_servo
cd /servo_tuning/head-sdk-face/head-server-web
bash run.sh
```

启动后在浏览器打开终端输出的本地链接（如 `http://localhost:5173` 或 `http://localhost:3000`）。

退出方式：在终端中连续按下两次 `Ctrl+C`，再按 `Ctrl+D`。

## 第四步：页面操作指南

### 硬件调试页（servo_tuning.html）

打开页面后，按以下顺序操作：

**① 建立硬件连接**
点击右上角「连接」按钮，与机器人的 gRPC 服务（终端 1）建立通讯。连接成功后按钮变绿，日志区显示连接信息。

**② 舵机直接微调**
右侧「舵机模块」区域列出所有舵机滑块，直接拖动可绕过映射系统，对物理机器人进行单关节控制。

| 操作 | 说明 |
|------|------|
| 拖动舵机滑块 | 实时控制单个舵机 |
| 刷新 | 从机器人读取当前所有舵机位置 |
| 导出配置 | 保存当前所有舵机数值到文件 |
| 导入配置 | 从文件恢复舵机数值 |
| 机器人控制 开关 | 关闭后所有控制指令停止发出（安全急停） |

**③ 加载映射关系（启用 BS 联动控制）**
点击「加载映射」，选择 `.yaml` 映射文件（默认路径在虚拟环境中：`~/miniconda3/envs/face_servo/lib/python3.10/site-packages/head_sdk/`）。

加载成功后，拖动左侧 BS 值滑块，即可同步控制数字人与实体机器人。

| 操作 | 说明 |
|------|------|
| 加载映射 | 选择定义 BS→舵机 转换关系的 yaml 文件 |
| Blendshapes 控制舵机 开关 | 打开后 BS 滑块的变化才会驱动舵机 |
| BS 滑块 | 拖动控制单个表情系数 |

**④ 连接数字人（可选）**
在左上方配置数字人 WebSocket 地址并连接，实现数据的双向通讯。

---

### 数字人页面（可选）

**确认通讯状态：** 打开页面后，观察右上角状态栏。若显示 **"发送端 1路"**，说明与硬件调试端已成功建立连接。

**独立控制测试：** 拖动页面下方的 BS 值滑块，可单独控制数字人面部表情变化，不影响硬件。

**软硬件全链路同步：** 在硬件控制页面加载了映射文件后，对硬件端进行控制时，数字人会实时做出相应表情，页面 BS 数值也会同步变化，实现虚实同步。

## 附：表情模仿测试（test_mimic.py）

使用 iPhone 的 LiveLinkFace 应用进行面部模仿，将 BS 数据实时驱动机器人。

**前置准备：** 将新版映射文件复制到 SDK 目录：

```bash
cp <你的映射文件.yaml> ~/miniconda3/envs/face_servo/lib/python3.10/site-packages/head_sdk/servo_mappings.yaml
```

**启动步骤：**

终端 1 — 启动 gRPC 服务（同上）：
```bash
conda activate face_servo
cd /servo_tuning/head-sdk-face/head-server/src
python head_grpc_server.py --config servo_config_v3.yaml
```

终端 2 — 运行模仿测试：
```bash
conda activate face_servo
cd /servo_tuning
python test_mimic.py
```

> iPhone 上 LiveLinkFace 的目标 IP 改为电脑 IP，端口填 `8008`。

## 常见问题排查

| 错误现象 | 可能原因 | 解决方法 |
|---------|---------|---------|
| `ModuleNotFoundError: No module named 'serial'` | 未安装 pyserial | `pip install pyserial` |
| `ModuleNotFoundError: No module named 'head_sdk'` | SDK 未安装 | 回到第一步重新执行 `pip install -e .` |
| `No such file or directory: '/dev/ttyCH340'` | YAML 配置的串口号有误 | 运行 `ls /dev/ttyACM*` 查看正确串口，修改 `servo_config_v3.yaml` |
| `npm: command not found` | 未安装 Node.js | `sudo apt install nodejs npm` |
| 点击连接后失败 | gRPC 服务未启动或被占用 | 检查终端 1 的输出，确认进程已正常运行且上次进程已完全退出 |
| 数字人右上角无「发送端」提示 | WebSocket 通讯失败 | 确认终端 2 的 `run_servo_tuning.sh` 正常运行且无报错 |
| 提示 `Another client is currently controlling the robot` | 其他程序占用了控制权 | 关闭其他控制程序，在页面点击「断开」后重新连接（程序会自动尝试释放控制权） |
| 端口被占用，服务启动失败 | 8081 或 8766 端口已被占用 | `lsof -i :8081` 查找占用进程，`kill -9 <PID>` 结束它 |

├── 使用说明.md                              # 本文件

    ├── head-sdk/                            # Python SDK（需要 pip install）
    ├── head-server/
    │   └── src/
    │       ├── head_grpc_server.py          # gRPC 服务主程序（终端 1 运行这个）
